# 실험 해석과 재실행 안내

이 문서는 제출 코드와 발표 자료를 포트폴리오로 정리하면서 추가한 검토 내용입니다. 당시의 코드나 결과를 변경한 기록이 아니며, 새로운 학습 결과를 제시하지 않습니다.

## 결과를 읽는 기준

제출 발표 자료는 당시 설명을 보존하기 위해 원본 그대로 포함했습니다. README는 노트북의 저장 출력과 현재 확인 가능한 코드를 우선합니다.

| 항목 | 원자료에서 확인한 내용 | 포트폴리오에서의 표현 |
| --- | --- | --- |
| ResNet50 정확도 | 슬라이드 5·29에는 90.62%, 최종 평가 출력에는 90.57% | 90.57% 사용 |
| 위험등급 수 | 슬라이드 2는 4단계를 열거하지만 매핑 코드와 슬라이드 6에는 `위험`을 포함한 5단계 | 5단계의 규칙 기반 태그 |
| 증강 비교 | 기본 `process_train`에도 밝기·대비 증강이 있음 | 기본 설정과 추가 증강 설정 비교 |
| 학습 실패 원인 | 단일 클래스 예측 집중은 리포트에서 관측됨 | 전처리·학습 조건을 포함한 원인 재검증 필요 |
| 언더샘플링 | 설명 셀에는 언더샘플링이 나오지만 뒤의 실행 코드는 전체 train CSV를 읽음 | 수행한 것으로 주장하지 않음 |
| GPU 최적화 | RTX 4070 SUPER 인식 로그, 혼합 정밀도와 prefetch 코드가 있음 | 적용 사실만 기재. 속도 2배·유휴 시간 0 같은 수치는 검증 결과로 사용하지 않음 |

## 모델별 전처리 확인

공통 기본 파이프라인은 이미지를 `255.0`으로 나눕니다. 그런데 MobileNetV2와 VGG16은 모델 내부에서 다시 각 모델의 `preprocess_input`을 호출합니다. 기본 ResNet50·101 학습 모델은 공통 파이프라인의 정규화된 입력을 그대로 받습니다.

또한 독립 이미지 비교 함수 `predict_with_all_models`는 학습 때와 달리 외부에서 모델별 `preprocess_input`을 적용합니다. MobileNetV2·VGG16은 내부 전처리와 중복되고, 기본 ResNet 계열은 학습 때와 입력 변환이 달라집니다. 따라서 그 함수의 몇 장짜리 예측 예시를 모델의 실도로 성능 근거로 사용하지 않습니다.

Keras는 모델마다 지정된 전처리 방식을 요구합니다. MobileNetV2는 픽셀을 -1~1로 변환하고, ResNet은 RGB를 BGR로 바꾸고 ImageNet 채널 평균을 빼는 방식을 사용합니다. 재실험에서는 입력 값의 범위, 색상 순서, 변환 위치를 학습과 추론에 걸쳐 일치시켜야 합니다. [MobileNet 공식 문서](https://keras.io/api/applications/mobilenet/mobilenet_models/), [ResNet 공식 문서](https://keras.io/api/applications/resnet/resnet_models/).

이 차이는 단일 클래스 예측 집중 현상을 다시 조사할 때 먼저 점검할 구현 요인입니다. 수정 후 학습을 수행하지 않았으므로 해당 차이가 성능 저하의 유일한 원인이라고 확정하지 않습니다.

## 추가 증강 실험의 비교 조건

| 설정 | 기본 ResNet101 | 추가 증강 ResNet101 |
| --- | --- | --- |
| 배치 크기 | 64 | 32 |
| 데이터 증강 | 파이프라인의 밝기·대비 변환 | 모델 내부의 회전·줌·대비·이동 |
| 입력 변환 | 파이프라인의 `/255.0` | `/255.0` 이후 모델 내부 ResNet `preprocess_input` |
| 미세조정 범위 | backbone 해제, BatchNormalization 동결 | 마지막 20개 층을 제외한 하위 층 동결 |
| 미세조정 학습률 | 0.00001 | 0.0001 |
| 학습 데이터 순서 | shuffle 사용 | `build_dataset`에 shuffle 없음 |
| 평가 정확도 | 91.76% | 77.07% |

여러 조건이 동시에 바뀌었으므로 14.69%p의 차이를 증강 하나의 인과 효과로 볼 수 없습니다. 입력 전처리를 먼저 바로잡고 나머지 조건을 고정한 뒤 회전·줌 등의 강도를 하나씩 바꾸는 실험이 필요합니다.

`RandomRotation(0.15)`의 계수는 15도가 아니라 한 바퀴의 15%를 뜻하므로 회전 범위는 약 ±54도입니다. 원본 코드 주석의 각도 설명과 다릅니다. [Keras RandomRotation 공식 문서](https://keras.io/api/layers/preprocessing_layers/image_augmentation/random_rotation/).

추가 증강 학습 곡선은 `history_aug_warmup`과 `history_aug_finetune`만 연결합니다. 이후 `history_aug_finetune2`의 추가 학습은 그래프에 들어 있지 않으므로, 해당 그림과 최종 평가가 정확히 같은 학습 구간을 요약한다고 보아서는 안 됩니다.

## 분할·라벨·평가 범위

- **분할 단위:** 분할은 크롭 이미지 행 단위입니다. 동일 원본 사진에서 잘린 표지판이나 유사한 주행 프레임의 교차 포함 여부를 검사한 기록은 없습니다. 원본 사진 또는 주행 시퀀스별 그룹 분할로 재검증할 필요가 있습니다.
- **클래스 매핑:** 라벨은 JSON 속성 조합을 이용한 규칙으로 생성했습니다. 낮은 속도제한을 모두 실제 스쿨존으로 보는 등 의미상 대리 분류가 포함되므로 클래스 이름과 실제 도로 맥락을 구분해야 합니다.
- **위험등급:** `risk_level`은 CSV 생성 시 부여한 태그입니다. 모델은 9개 클래스의 확률을 출력하며, 별도의 위험도 출력 헤드를 학습하거나 사고 데이터로 위험 확률을 검증하지 않았습니다.
- **체크포인트 선택:** EarlyStopping은 `val_loss`, ModelCheckpoint는 `val_accuracy`를 기준으로 합니다. 메모리의 복원된 모델과 저장된 최고 정확도 체크포인트가 같은 모델이라고 가정할 수 없습니다. 공개 수치는 저장된 `evaluate()` 출력 기준입니다.
- **비교의 한계:** 단일 실험 기록이며 반복 시드 실험, 신뢰구간, 다른 주행 지역·시점에서의 독립 검증 결과는 제공되지 않았습니다.

## 재실행 준비

현재 저장소는 실험을 열람하고 설명하기 위한 제출 기록입니다. 노트북을 처음부터 끝까지 바로 실행할 수 있는 상태로 검증한 것은 아닙니다.

1. **데이터 준비:** 발표 자료에서 명시한 AI Hub 데이터를 별도로 확보하고, JPG와 같은 파일 이름의 JSON을 각각 이미지·라벨 폴더에 둡니다. 원자료 이용 조건은 [AI Hub](https://www.aihub.or.kr/)에서 확인합니다.
2. **환경 구성:** `requirements.txt`는 사용 패키지 목록입니다. 당시 TensorFlow·CUDA·cuDNN 버전 기록이 없어 환경을 동일하게 복원할 수 없습니다. 노트북 메타데이터의 Python 3.13.9는 저장 시 커널 정보이며, 모든 학습이 그 버전에서 수행됐다는 근거로 쓰지 않습니다.
3. **경로 변경:** `IMAGE_DIR`, `LABEL_DIR`, `OUTPUT_DIR`, `BASE_DIR`와 CUDA 라이브러리 경로를 실행 환경에 맞게 변경합니다. CUDA 경로를 하드코딩한 부분은 환경에 따라 불필요할 수 있습니다.
4. **전처리와 분할:** JSON 탐색, bbox 크롭, 클래스 매핑, 학습·검증·테스트 CSV 생성 셀을 순서대로 검토합니다. 전체 작업은 대량의 파일과 디스크 공간을 사용합니다.
5. **실험 순서 조정:** CPU 시험 셀은 뒤에서 정의되는 `train_ds`, `val_ds`를 참조합니다. 처음 실행할 때는 데이터 파이프라인 이후로 옮기거나 해당 시험을 건너뛰어야 합니다. ResNet50의 `resnet50_best.h5` 로드 셀은 체크포인트가 없으면 실행할 수 없으므로 첫 학습과 재개 학습을 구분합니다.
6. **학습 전 검토:** 위의 전처리 불일치를 수정한 뒤 재실험하면 새로운 실험이 됩니다. 원본 출력과 섞지 말고 별도 노트북·가중치·평가 기록으로 저장해야 합니다.

GPU 모델명은 후반 환경 출력과 발표 자료에서 RTX 4070 SUPER로 확인했습니다. 처음의 GPU 인식 출력은 빈 목록이며, 중간에 환경 전환과 세션 상태 복구를 거친 실험 기록입니다.
