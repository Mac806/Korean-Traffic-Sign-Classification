# 한국 도로 표지판 분류 실험

**2026년 1학기 · 3학년 1학기 · 머신러닝(2) 기말 개인 프로젝트**

AI Hub의 국내 도로 영상 데이터에서 표지판 영역을 추출하고, **9개 범주의 이미지 분류를 위해 CNN 모델 4종을 학습·비교**했습니다. 데이터 전처리부터 전이학습, 파인튜닝, 클래스별 평가, 추가 증강 실험까지 진행한 기록입니다.

저장된 테스트 결과에서 ResNet101은 **정확도 91.76%, Macro F1 0.87**을 기록했습니다. 성능이 낮았던 모델과 추가 증강 실험도 함께 공개하며, 관측한 결과와 아직 검증하지 않은 원인을 구분합니다.

**기술:** Python, TensorFlow/Keras, OpenCV, pandas, NumPy, scikit-learn, Matplotlib, Seaborn, Jupyter

[실험 노트북](notebooks/traffic_sign_experiments.ipynb) · [최종 발표 자료](docs/final-presentation.pptx) · [실험 해석과 재실행 안내](docs/experiment-notes.md)

## 프로젝트에서 한 일

- **데이터 구조 분석과 라벨 설계:** JSON의 `type`, `shape`, `color`, `text`를 조합해 표지판을 9개 범주로 매핑했습니다.
- **전처리 파이프라인 구현:** `traffic_sign` 객체를 골라 bounding box로 자르고, 224×224 이미지와 라벨 CSV를 생성했습니다.
- **모델 비교:** ResNet50, ResNet101, MobileNetV2, VGG16에 ImageNet 전이학습과 파인튜닝을 적용했습니다.
- **학습 환경 구성:** GPU 환경, `mixed_float16`, `tf.data` 병렬 처리와 prefetch를 적용하고, 클래스 불균형에 대응하기 위해 class weight를 사용했습니다.
- **결과 분석:** 정확도뿐 아니라 클래스별 Precision·Recall·F1, 혼동행렬, 학습 곡선으로 예측 편중과 오분류를 확인했습니다.
- **추가 실험:** ResNet101에 회전·줌·대비·이동 증강을 추가한 별도 학습 설정을 실험하고 기본 설정과 비교했습니다.

## 문제와 접근

프로젝트의 출발점은 국내 도로 표지판을 분류하고, 표지판 종류에 따라 주의가 필요한 정도를 함께 표현해 보는 것이었습니다. 학습한 모델은 **잘라낸 표지판 이미지의 클래스를 예측**합니다. 전체 도로 사진에서 표지판 위치를 자동으로 찾는 탐지기는 구현 범위에 포함하지 않았습니다.

위험등급은 CNN이 사고 확률을 학습한 결과가 아니라, 라벨을 만들 때 클래스에 부여한 **프로젝트 자체의 규칙 기반 태그**입니다. `고위험·위험·주의·보통·안전`의 5단계를 사용하며, 실제 운전 안전성이나 사고 가능성을 검증한 지표는 아닙니다.

```mermaid
flowchart LR
    A[도로 이미지와 JSON] --> B[표지판 bbox 크롭]
    B --> C[224×224 변환과 라벨 CSV]
    C --> D[9개 클래스 매핑]
    D --> E[Train / Validation / Test 분할]
    E --> F[전이학습과 파인튜닝]
    F --> G[분류 리포트와 혼동행렬]
    D --> H[규칙 기반 위험등급 태그]
```

## 저장된 실험 결과

**테스트 크롭 22,963장에 대한 제출 노트북의 저장 출력입니다. 이번 포트폴리오 정리에서 재학습하거나 재평가한 수치가 아닙니다.** 모델별 전처리와 추가 실험 설정에 차이가 있어, 이 결과만으로 모델 구조의 일반적인 우열을 단정할 수는 없습니다.

| 실험 | Test Accuracy | Macro F1 | 관측 내용 |
| --- | ---: | ---: | --- |
| ResNet50 파인튜닝 | 90.57% | 0.86 | 워밍업 이후 파인튜닝으로 분류 성능 개선 |
| **ResNet101 파인튜닝** | **91.76%** | **0.87** | 저장된 비교 실험 중 가장 높은 정확도 |
| ResNet101 추가 증강 설정 | 77.07% | 0.66 | 기본 ResNet101 대비 14.69%p 낮음 |
| VGG16 파인튜닝 | 29.08% | 0.05 | 테스트 예측이 `진입_주정차금지`에 집중 |

## 실험 과정과 시행착오

노트북에는 각 모델의 **최종 실행 결과만** 남아 있습니다. 실제로는 한 모델도 한 번에 끝나지 않았습니다. 코드 오류로 학습을 처음부터 다시 돌리거나, 학습 결과를 저장하지 않아 다음 날 노트북을 다시 열었을 때 다시 학습하거나, 원하는 성능이 나오지 않아 코드를 고쳐 다시 돌리는 과정을 반복했습니다.

초반에는 성능을 끌어올리는 데만 집중해 이런 실행을 따로 기록하지 않았습니다. 반복이 쌓이면서 무엇을 바꿨고 왜 그렇게 판단했는지 남기지 않으면 결과를 설명할 수 없다는 것을 깨달았고, 프로젝트 중간부터 노트북을 기록이자 제출 결과물로 만들기 시작했습니다. 코드 셀마다 목적과 결과 해석을 적은 설명 셀을 붙였고, 그 전에 겪은 일(CPU 학습 시도 등)은 뒤늦게 셀을 추가해 남겼습니다. 아래 내용은 이렇게 남긴 최종 결과와 그 과정의 판단을 정리한 것입니다.

### 1. CPU 학습이 너무 느려 GPU 환경을 새로 구성

처음 CPU로 학습을 시도했을 때 15만 장 규모의 데이터를 반복 학습하기에는 너무 느렸습니다. 노트북의 CPU 1 에포크 측정 셀은 이 경험을 기록으로 남기기 위해 나중에 추가한 것으로, 측정을 끝까지 마치지는 않았습니다. 별도의 GPU용 가상환경을 만들고 CUDA 라이브러리 경로를 직접 지정해 GPU(RTX 4070 SUPER)를 인식시켰습니다. 이에 맞춰 기존 이미지 제너레이터 대신 `tf.data` 병렬 처리와 `prefetch`로 데이터 공급 방식을 다시 짰고, `mixed_float16`을 적용했습니다. 속도 향상 폭은 따로 측정하지 않았습니다.

### 2. 백본을 동결한 1차 학습은 정확도 37%에 그침

ImageNet으로 사전학습된 ResNet50의 가중치를 고정하고 분류기만 학습했더니, 훈련 정확도가 약 25%에서 더 오르지 않았고 테스트 정확도는 37%였습니다. 분류 리포트를 보니 `보호구역`의 Recall은 0.88인데 Precision은 0.20으로, 헷갈리면 보호구역으로 몰아서 예측하고 있었습니다. 숫자를 구분해야 하는 속도제한 클래스들의 F1은 0.10~0.35에 머물렀습니다.

동결된 특징만으로는 표지판 안의 숫자 같은 세부 차이를 잡지 못한다고 보고, 백본 동결을 해제하되 BatchNormalization 층은 동결을 유지했습니다. 학습률은 `1e-5`로 낮추고 조기 종료 기준(patience)은 5에서 3으로 줄였습니다. 이 미세조정 이후 테스트 정확도는 **90.57%**가 되었고, 속도제한 클래스들의 F1은 0.85~0.91로 올라갔습니다.

### 3. ResNet101로 확장

같은 절차를 더 깊은 ResNet101에 적용했습니다. 이전 모델이 차지한 GPU 메모리를 먼저 비워 메모리 부족을 막았고, 워밍업과 미세조정의 가중치 파일을 단계별로 분리해 저장했습니다. 테스트 정확도는 **91.76%**였고, `스쿨존_속도제한30이하`의 Precision이 0.68에서 0.80으로 올라 다른 표지판을 스쿨존으로 잘못 예측하는 경우가 줄었습니다.

### 4. 정확도 숫자 뒤의 붕괴를 찾아냄

MobileNetV2와 VGG16은 학습이 사실상 되지 않았습니다. 두 모델 모두 손실이 2.197 근처에서 멈췄는데, 이는 9개 클래스에 똑같이 1/9 확률을 주는 무작위 예측의 손실값 −ln(1/9)과 같습니다. 정확도도 클래스 분포와 대조해 확인했습니다.

- MobileNetV2의 0.94%는 테스트셋에서 `높이_중량제한`이 차지하는 비율(217 / 22,963)과 같습니다.
- VGG16의 29.08%는 `진입_주정차금지`의 비율(6,678 / 22,963)과 같습니다.

즉 두 모델 모두 모든 이미지를 한 클래스로만 예측하고 있었고, VGG16의 29%는 학습한 결과가 아니라 클래스 비율에서 나온 숫자였습니다. 당시에는 모델 용량과 class weight의 영향으로 해석했지만, 이후 코드를 다시 검토하면서 입력 정규화가 두 번 적용되는 문제를 발견해 원인은 재검증 과제로 남겼습니다.

### 5. 증강을 늘렸더니 오히려 77%로 하락

실제 도로 환경에 더 강해지길 기대하며 ResNet101에 회전·줌·대비·이동 증강을 추가했는데, 테스트 정확도가 91.76%에서 **77.07%**로 떨어졌습니다. 특히 속도제한 표지판의 F1이 0.4~0.7대로 낮아져, 강한 회전과 확대가 원 안의 숫자 형태를 뭉개뜨렸다고 판단했습니다. 실제로 `RandomRotation(0.15)`는 15도가 아니라 한 바퀴의 15%, 즉 약 ±54도 회전이었습니다.

다만 다시 비교해 보니 이 실험에서는 증강 외에도 배치 크기, 학습률, 미세조정 범위, 셔플 여부, 입력 전처리가 함께 바뀌어 있었습니다. 이 설정은 에포크당 약 22분, 전체 6시간 이상이 걸려 조건을 하나씩 바꿔 반복하기 어려웠고, AI가 추천한 변경도 함께 적용하면 한 번에 개선 효과를 얻을 수 있으리라 판단했습니다. 그 결과 정확도가 떨어진 원인을 하나로 특정할 수 없었습니다.

### 6. 실제 사진으로 확인한 분류기의 한계

크롭 데이터가 아닌 실제 사진도 넣어 보았습니다. 어린이 보호 표지판과 30 속도제한 표지판이 위아래로 겹친 사진에서는 모델마다 다른 답을 냈지만, 속도제한 표지판만 잘라 넣자 ResNet101이 `스쿨존_속도제한30이하`로 분류했습니다. 분류 모델은 사진 전체를 보고 답 하나를 내기 때문에, 실제 도로 영상에 쓰려면 앞단에 표지판을 찾아 잘라 주는 탐지 모델이 필요하다는 것을 확인했습니다. 이 비교는 몇 장의 예시이며, 추론 함수의 전처리가 학습 때와 달라 성능 근거로는 사용하지 않습니다.

### 7. 오래 걸리는 실험을 반복하며 배운 것

- **학습 결과는 단계마다 저장한다.** 세션이 끊길 때마다 처음부터 다시 학습하는 일이 반복된 뒤, 워밍업과 미세조정의 최고 성능 가중치를 별도 파일로 저장하고 이어서 학습할 수 있도록 체크포인트를 불러오는 셀을 만들었습니다.
- **실험 한 번의 비용이 클수록 작게 먼저 검증한다.** 데이터 일부와 1~2 에포크로 코드 오류와 학습 붕괴를 먼저 확인했다면, 오류가 날 때마다 몇 시간씩 다시 돌리는 일을 줄일 수 있었습니다.
- **AI가 제안한 변경도 하나씩 확인한다.** 여러 제안을 한꺼번에 적용하면 결과가 나빠졌을 때 원인을 되짚을 수 없습니다.
- **처음부터 기록한다.** 중간부터 판단과 결과를 남기기 시작했지만, 초반의 반복 실행과 실패한 설정은 기록이 없어 지금은 최종 결과만 설명할 수 있습니다. 다음 실험부터는 첫 실행부터 실행별로 주요 설정, 소요 시간, 평가 결과를 한 줄씩 남길 계획입니다.

## 실험에서 확인한 점과 다음 과제

**평균 정확도만으로는 예측 편중을 알기 어렵습니다.** VGG16과 MobileNetV2의 분류 리포트·혼동행렬을 통해 단일 클래스에 예측이 집중되는 현상을 확인했습니다. 다만 이를 경량 모델의 표현력이나 class weight 하나의 문제로 확정하지 않고, 입력 전처리부터 다시 비교할 필요가 있습니다.

**추가 증강 실험에서는 여러 조건이 함께 바뀌었습니다.** 기본 모델에도 밝기·대비 증강이 있었고, 추가 실험에서는 기하학적 증강 외에 전처리, 배치 크기, 학습률과 미세조정 범위도 달랐습니다. 따라서 성능 하락을 증강만의 효과로 해석하지 않습니다.

후속 작업은 모델별 입력 전처리 통일, 원본 이미지·주행 구간 기준 분할, 한 번에 하나의 조건을 바꾸는 비교 실험을 우선으로 잡았습니다. 표지판 탐지기와 OCR 연계는 그 이후의 확장 방향입니다. 코드에서 확인한 구체적인 차이는 [실험 해석 문서](docs/experiment-notes.md)에 정리했습니다.
